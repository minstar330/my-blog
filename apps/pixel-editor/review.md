# 콕콕 (pixel-editor) 리뷰 결과

## 1. 요약

- **결론: 통과** (기능·PNG·접근성 버그는 찾지 못함. Build가 남긴 레이아웃 우려 2건과 새로 찾은 작은 문제 1건을 `style.css`에서 고친 뒤 다시 확인함)
- 고친 문제: **3건** (모두 `style.css`)
  1. 375×812에서 "PNG로 저장" 버튼이 첫 화면보다 30px 아래에 있음 → 모바일 세로 간격을 줄여 버튼 아래 끝 806px(화면 812px) 안으로 들어옴
  2. 구형 브라우저에서 `::backdrop`이 `:root` 변수를 상속하지 않아 대화상자 배경이 투명해질 수 있음 → `--overlay-bg`를 `::backdrop`에도 정의
  3. 넓은 화면에서 캔버스가 512px이 아니라 510px(테두리 포함 512px)이라 한 칸이 32px이 아님 → 테두리 2px을 더해 캔버스 자체가 512px
- 로직 테스트: Node 40/40 통과, `test.html` 40/40 통과(수정 전후 모두).
- PNG: 실제 다운로드 경로가 만든 Blob 4개(16·128·256·512px)를 다시 디코드해 `toRgba`와 **바이트 단위로 완전히 같음**(차이 0바이트) 확인.

## 2. 검증 환경

- 서버: 내장 브라우저 `preview_start { name: "blog" }`(이미 떠 있던 `node serve.js 8000` 재사용), `http://localhost:8000/apps/pixel-editor/`, `…/test.html`. `file://` 탭은 쓰지 않음.
- 기기 배율 `devicePixelRatio` 2. 화면: 1280×800, 900·790·700·601px(중간 폭), 375×812(모바일 프리셋, 터치 포인트 5), 333px.
- 테마: OS 다크(기본)·OS 라이트(`colorScheme` 에뮬레이션), 블로그 `theme` 키 `light`·`dark`·없음.
- 방법
  - 포인터: 캔버스에 합성 `PointerEvent`(mouse/touch, `pointerId`·`isPrimary`·`button` 지정). 포인터 캡처가 되는 상황을 흉내 내려고 캔버스 밖 좌표의 `pointermove`도 캔버스에 보냄.
  - 키보드: 실제 키 입력(`Enter`, `Escape`, `Tab`, `Ctrl+Z`, `Ctrl+Shift+Z`, `Ctrl+Y`, `b`, `g`, 방향키)과 합성 `KeyboardEvent`(Space 누른 채 이동, `event.repeat`, 한글 입력 `key: 'ㅠ'`/`code: 'KeyB'`).
  - PNG: `HTMLAnchorElement.prototype.click`을 잠시 바꿔 실제 다운로드 대신 `href`·`download` 값을 기록(파일은 받지 않음), 그 `href`(blob)를 `fetch` → `createImageBitmap` → 같은 크기 캔버스 `drawImage` → `getImageData`로 읽어 `toRgba`와 비교. `URL.revokeObjectURL`도 잠시 감싸 해제 여부 기록. 모두 원래대로 되돌림.
  - `localStorage` 차단: `index.html`을 읽어 `<head>` 맨 앞에 `Storage.prototype.getItem/setItem/removeItem`이 예외를 던지게 하는 스크립트를 넣은 `srcdoc` iframe(같은 출처)에서 실행. 원본 파일은 그대로.
  - 캔버스 렌더링: 캔버스 픽셀을 `getImageData`로 직접 읽어 확인(스크린샷은 축소 때문에 기기 1px 격자선이 일부만 보여 판단에 쓰지 않음).
  - 명도 대비: Node로 WCAG 2.x 공식 계산.
- **브라우저 창이 숨겨진 구간**이 있었다(`tabs_context`: "currently hidden"). 이때 `requestAnimationFrame`·`ResizeObserver`·`matchMedia` `change`·`<dialog>` `close` 이벤트가 멈추거나 늦게 왔다(아래 6장). 그래서 그 구간의 캔버스 확인은 `requestAnimationFrame`만 `setTimeout(16ms)`로 바꾼 `srcdoc` iframe에서 했고, 창이 보이는 상태가 된 뒤 원래 페이지에서 `ResizeObserver`·OS 테마 변경·`Esc` 닫기를 다시 확인했다.
- 검증 뒤 되돌림: `localStorage`의 `pixel-editor:drawing`·`pixel-editor:settings`·`theme`(처음에 모두 없었음 → 삭제, `tile-merge:best-score`=104는 그대로 확인), 화면 크기 에뮬레이션 해제(`desktop`), 색 모드는 처음과 같은 다크, 직접 연 탭(tab-7·tab-8) 닫음.

## 4. 발견한 문제와 수정

### 문제 1 — 375×812에서 "PNG로 저장"이 첫 화면 밖 (Build 우려)
- **문제**: 버튼 아래 끝이 842px로 화면(812px)보다 30px 아래.
- **원인**: 모바일 세로 간격 합(상단 4px, 헤더 아래 8px, 캔버스–패널 16px, 패널 안 간격 12px×4, 도구 버튼 높이 52px×2).
- **수정**(`style.css`): `.app` 위 여백 4→0px(160), `.app-header` 아래 8→4px(164), `.editor` 간격 16→12px(228), `.side` 간격 12→8px(258), `.tool-button` 최소 높이 52→48px·안쪽 여백 4px 2px→2px(307~308). 넓은 화면은 `@media (min-width: 48rem)`에서 `.side` 12px·`.tool-button` 52px로 되돌림(590, 594). 터치 대상 44px·좌우 16px은 그대로, 스와치 정사각도 그대로.
- **재확인**: 버튼 위치 `top 762, bottom 806`(화면 812 안), 44px 미만 대상 0개, 가로 스크롤 없음, 도구 버튼 8개 모두 48px·글자 한 줄(가장 긴 "전체 지우기" 68px / 버튼 81px). 1280px에서는 도구 52px·간격 12px 그대로. 라이트·다크 스크린샷으로 겹침·잘림 없음 확인.

### 문제 2 — 구형 브라우저의 `::backdrop` 투명 (Build 우려)
- **문제**: Chrome 121·Safari 17.3 이하 등은 `::backdrop`이 `:root` 변수를 상속하지 않아 `background: var(--overlay-bg)`가 무효 → 배경이 투명해져 뒤 화면과 대화상자가 겹쳐 보일 수 있음.
- **수정**(`style.css:94-109`): 토큰 영역에 `::backdrop`용 `--overlay-bg`를 라이트·OS 다크(`:root:not([data-theme='light']) ::backdrop`)·블로그 다크(`:root[data-theme='dark'] ::backdrop`) 세 가지로 한 번 더 정의. 값은 기존 토큰과 같고, 최신 브라우저에서는 같은 값으로 덮어써져 결과가 같음.
- **재확인**: 현재 Chromium에서 `::backdrop` 배경 라이트 `rgba(244,246,251,0.88)`, 다크 `rgba(15,18,32,0.88)`. 구형 브라우저 자체에서는 확인 못 함(6장).

### 문제 3 — 넓은 화면 캔버스가 510px (새로 발견)
- **문제**: spec은 "캔버스 최대 512px(한 칸 32px)"인데, 512px 칸 안에 1px 테두리가 들어가 캔버스는 510px. 배율 1 화면에서는 칸 폭이 31px·32px로 섞여 격자가 고르지 않게 보임.
- **수정**: `.canvas-frame` 폭 `min(100%, calc(32rem + 2px))`(`style.css:233`), 2열 그리드 첫 열 `minmax(0, calc(32rem + 2px))`(584).
- **재확인**: 1280px에서 캔버스 512px·`canvas.width` 1024(칸 64 기기 픽셀로 모두 같음), 열 `514px 358px`(오른쪽 패널 16rem 이상 유지), 375px에서는 이전과 같이 343px 칸 안에 꽉 참.

### 고치지 않은 사소한 점 (참고)
- `main.js`가 `canvas.dataset.tool`로 캔버스에 `data-tool`을 붙인다. 도구 버튼 목록은 그 전에 `[data-tool]`로 모아 두어 지금은 문제없지만, 나중에 `[data-tool]`을 다시 찾는 코드가 생기면 캔버스가 섞인다. CSS에서도 쓰이지 않는 값이라 그대로 둠.
- 375px에서 캔버스 CSS 폭은 341px(테두리 포함 343px). spec 스케치의 "캔버스 343×343"과 2px 차이지만 테두리를 포함한 그리기 면 크기로 보면 같아 그대로 둠.
- 대화상자 폭은 UA 기본 `max-width`(100% − 2em − 6px) 때문에 375px에서 337px(좌우 19px). 여백 16px 이상이라 그대로 둠.

## 6. 남은 위험·확인 못 한 것

- **숨겨진 브라우저 창의 타이밍**: 창이 숨겨진 동안 `requestAnimationFrame`이 멈춰 캔버스가 다시 그려지지 않았고, `ResizeObserver`·`matchMedia` `change`가 오지 않았으며, `Esc` 뒤 `close` 이벤트가 0.5초 이상 늦거나 확인 시점까지 오지 않은 적이 있었다. 창이 보이는 상태에서는 셋 다 정상(캔버스 즉시 갱신, `Esc` 뒤 300ms 안에 미리보기 URL 해제·`src` 제거)이라 앱 문제가 아니라 환경 문제로 보고 코드로 덮지 않았다. 참고로 `close`가 늦게 와도 `finishDialog`는 대화상자가 다시 열려 있으면 아무것도 하지 않고, 다음 미리보기가 이전 URL을 해제하므로 URL이 새지 않는다.
- **실제 기기 터치**: 합성 Pointer 이벤트로만 확인. 실제 손가락으로 캔버스 위 스크롤·핀치·더블탭 확대가 막히는지, 캔버스 밖 스크롤, iOS 길게 누르기 메뉴(`-webkit-touch-callout`)는 iOS Safari·Android Chrome 실기기 확인 필요.
- **실제 파일 다운로드**: 다운로드 권한을 받지 않으려고 `<a download>` 클릭을 가로채 값만 확인했다. 실제 저장 동작, iOS의 "다운로드" 확인 창, 앱 안 브라우저의 길게 눌러 저장은 확인 못 함.
- **`toBlob`이 없는 환경의 `toDataURL` 대체**: 코드로만 확인.
- **구형 브라우저**: `::backdrop` 대비책은 현재 Chromium에서 결과가 같은 것만 확인. `<dialog>`(Safari 15.4+), `aspect-ratio`, `rgb(r g b / a)` 문법을 쓰므로 그보다 오래된 브라우저는 범위 밖.
- **기기 배율 1·3 화면**: 확인 환경은 배율 2만 있었다. 계산식(`Math.round(cssSize * dpr)`, 정수 칸 경계)은 배율과 무관하다. 브라우저 확대로 배율이 바뀔 때의 `watchPixelRatio`는 코드로만 확인.
- **인라인 테마 스크립트의 저장소 예외**: 파싱 전에 막을 수 없어 차단 iframe에서 스크립트가 오류 없이 지나가는 것까지만 확인(`theme` 없음 → OS 설정).
- **`file://` 안내 문구**: 지침상 `file://` 탭을 열지 않아 코드로만 확인.
- **화면 낭독기 실제 낭독**: live 영역 문구·`role="application"`·포커스 이동은 DOM으로 확인, NVDA·VoiceOver로 들어 보지 않음.
- **블로그 카드 연결**: `apps/index.json`에는 아직 `pixel-editor` 항목이 없다(Build 범위가 `apps/pixel-editor/` 안이라 정상). 다음 단계에서 spec 9.1대로 추가하고 블로그 목록에서 카드·`preview.svg`가 보이는지 확인해야 한다. `preview.svg` 자체는 열어서 화분 도안·팔레트 띠·제목이 보이는 것을 확인했다.
