# Plan 서브에이전트 지침 — 픽셀 아트 에디터

## 할 일
사용자 요청: "픽셀 아트 에디터를 만들어줘. 16x16 격자에 도트를 찍어서 그림을 그리고, 완성하면 PNG로 저장할 수 있게 해줘. 색상 팔레트도 넣어줘."

이 요청을 구현할 계획을 세워 **`apps/pixel-editor/spec.md` 한 파일만** 작성한다. 구현 코드는 쓰지 않는다.

## 수정 범위
- 쓰기 허용: `apps/pixel-editor/spec.md` 하나.
- 그 외 파일은 읽기만 한다. git 명령을 실행하지 않는다.

## 먼저 읽을 것
- `CLAUDE.md` — 작업 사이클, 웹앱 규칙, 배포(상대 경로, `/my-blog/` 하위 경로) 규칙.
- **`apps/tile-merge/spec.md`** — 앞서 만든 웹앱의 계획서. 문서 구성, 테마 처리(블로그 `localStorage` `theme` 키를 읽기만 하고 따름, `storage` 이벤트 반영), 접근성·수용 기준 작성 방식을 같은 수준으로 맞춘다. `apps/tile-merge/index.html`, `style.css`도 참고해 두 앱의 공통 뼈대(헤더의 `← 블로그로` 링크 `../../`, 테마 인라인 스크립트, `file://` 안내)를 맞춘다.
- `apps/index.json`, `js/main.js`의 `renderAppCard` — 블로그 카드는 이미 매니페스트 방식으로 연결돼 있다. Embed는 `apps/index.json`에 항목 하나와 미리보기 이미지(640×400 비율, `preview.svg` 등)를 추가하는 것으로 끝나야 한다. 블로그 코드를 고칠 필요가 있으면 그 이유를 적는다.

## 반드시 지킬 제약
- 순수 HTML/CSS/JavaScript, 외부 라이브러리 없이 계획한다(PNG 저장은 Canvas `toBlob` 등 브라우저 내장 기능으로). 빌드 단계 없음.
- `apps/pixel-editor/` 안에서 자체 완결. 모든 경로는 상대 경로.
- 모바일 사용 가능: 터치로 찍기·드래그로 이어 그리기, 375px 폭에서 가로 스크롤 없음, 터치 대상 44×44px 이상(16×16 격자 한 칸이 44px보다 작아지는 문제를 어떻게 다룰지 명시), 캔버스 위에서 그릴 때 페이지가 스크롤되지 않게.
- 다크 모드: 앱 자체 CSS 변수로 라이트/다크, 블로그 테마를 따르는 방식은 tile-merge와 같게.
- `localStorage`는 `try/catch`로 감싼다.
- CLAUDE.md 코드 스타일. 그리기 데이터·도구 로직(픽셀 배열, 채우기 알고리즘, PNG용 픽셀 변환, 되돌리기 이력 등)은 DOM에 의존하지 않는 순수 모듈로 분리해 Node로 테스트할 수 있게 한다.
- 접근성: 명도 대비 WCAG AA, `:focus-visible` 유지, 키보드만으로 최소한의 그리기가 가능한지(예: 방향키로 커서 이동 + Space로 찍기) 결정해서 적는다. 팔레트 색 버튼에 색 이름 레이블.

## spec.md에 들어갈 내용 (한국어)
1. 개요 — 앱 표시 이름(한국어 + 영문 부제), 한 줄 설명, 블로그 카드 문구.
2. 기능 — 꼭 넣을 것과 넣지 않을 것을 구분. 기본으로 검토할 것: 펜, 지우개, 채우기(같은 색 영역), 스포이트, 전체 지우기(확인), 되돌리기/다시 하기, 격자선 표시 토글, 작업 자동 저장(새로고침 후 유지 여부). 범위를 과하게 키우지 않는다.
3. 팔레트 — 기본 색 목록(개수와 HEX 값, 독창적으로 구성), 사용자 지정 색(`<input type="color">` 등) 추가 여부, 현재 색 표시, 투명(빈 칸) 처리.
4. PNG 저장 — 출력 크기(원본 16×16만인지, 배율 선택인지와 기본값), 투명 배경 유지, 확대 시 흐려지지 않게 하는 방법, 파일 이름 규칙, 모바일(iOS Safari 등)에서 다운로드가 안 될 때의 대안.
5. 조작 — 마우스·터치·펜(Pointer Events), 드래그 중 칸을 건너뛰지 않게 하는 보간, 키보드 단축키.
6. 화면 구성·디자인 — 레이아웃 스케치(375px와 넓은 화면), 색 토큰(라이트/다크), 빈 칸(투명) 표시 방식(체크무늬 등), 캔버스 렌더링 방식(Canvas vs DOM 격자 중 추천과 이유).
7. 파일 구조 — 파일 목록과 역할(예: `index.html`, `style.css`, `editor.js`(순수 로직), `png.js` 또는 내보내기 모듈, `storage.js`, `main.js`, `test.html`, `editor.test.js`, `preview.svg`).
8. 모듈 인터페이스 — 순수 모듈이 내보낼 함수 시그니처와 자료 형태.
9. Embed 계획 — `apps/index.json` 항목(제목·설명·미리보기 파일), 미리보기 이미지 내용.
10. 수용 기준 — Review 체크리스트(기능, PNG 결과물 픽셀 검증, 모바일, 다크 모드, 콘솔 에러 없음, 규칙 위반 없음).
11. 범위 밖.
12. 열린 질문 — 사용자 확인이 필요한 결정(많아야 4~5개, 각각 추천안 포함).

## 끝나면
최종 보고로 앱 이름, 주요 결정 3~5개, 열린 질문(각각 추천안)을 한국어로 짧게 돌려준다.
