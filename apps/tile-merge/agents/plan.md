# Plan 서브에이전트 지침 — 숫자 타일 합치기 퍼즐

## 할 일
사용자 요청: "방향키로 숫자 타일을 밀어서 합치는 퍼즐 게임(2048류)을 만들어줘. 점수판도 넣어줘."

이 요청을 구현할 수 있는 계획을 세워 **`apps/tile-merge/spec.md` 한 파일만** 작성한다. 구현 코드는 쓰지 않는다.

## 수정 범위
- 쓰기 허용: `apps/tile-merge/spec.md` 하나.
- 그 외 파일은 읽기만 한다. 특히 `index.html`, `css/`, `js/`, `posts/`, `CLAUDE.md`는 수정 금지.
- git 명령(add, commit 등)을 실행하지 않는다.

## 먼저 읽을 것
- `CLAUDE.md` — 작업 사이클, 웹앱 규칙, 배포(상대 경로, `/my-blog/` 하위 경로) 규칙.
- `index.html`, `css/style.css` — 블로그의 색 변수와 톤. 나중에 Embed 단계에서 이 페이지에 카드가 들어간다.

## 반드시 지킬 제약
- **독창적인 외형**: 메커니즘(격자에서 타일을 밀어 같은 숫자를 합치기)은 쓰되, 원작 2048의 이름·로고·베이지/주황 색상표·레이아웃을 따라 하지 않는다. 앱 이름(한국어 표시명 + 영문 부제)과 색 체계를 새로 정한다. 폴더 이름은 `tile-merge`로 고정.
- 순수 HTML/CSS/JavaScript, 외부 라이브러리 없이 계획한다(CDN이 꼭 필요하면 이유를 적되, 이 앱에서는 필요 없을 것으로 본다). 빌드 단계 없음.
- `apps/tile-merge/` 안에서 자체 완결. 모든 경로는 상대 경로(`/`로 시작 금지).
- 모바일 사용 가능: 터치 스와이프 지원, 375px 폭에서 가로 스크롤 없음, 터치 대상 44×44px 이상, 보드 위에서 스와이프할 때 페이지가 스크롤되지 않게.
- 다크 모드: 앱 자체 CSS 변수로 라이트/다크 정의, `prefers-color-scheme` 기본. (블로그에 iframe으로 들어갈 수 있다는 점을 고려해, 부모 테마를 따를지 여부도 결정해서 적는다. 단, 서버 기능에 기대지 않는다.)
- `localStorage`(최고 점수 등)는 `try/catch`로 감싼다.
- 코드 스타일은 CLAUDE.md를 따른다(ES 모듈, const/let, 2칸, 세미콜론, 작은따옴표, kebab-case 클래스, 한국어 주석·UI). 게임 로직은 DOM에 의존하지 않는 순수 함수로 분리한다.
- 접근성: 명도 대비 WCAG AA, `:focus-visible` 유지, 점수 변화·게임 종료를 스크린리더에 알리는 방법.

## spec.md에 들어갈 내용 (한국어)
1. 개요 — 앱 이름, 한 줄 설명, 블로그 카드용 설명 문구.
2. 게임 규칙 — 격자 크기, 새 타일 생성 규칙(값과 확률), 이동·합치기 규칙(한 번 이동에 타일은 한 번만 합쳐짐 등 경계 사례 포함), 움직임이 없으면 새 타일을 만들지 않음, 승리 조건과 승리 후 계속하기, 게임 오버 판정.
3. 점수판 — 현재 점수 계산 방식, 최고 점수 저장, 표시 위치, 새 게임 버튼. 추가 기능(되돌리기, 합산 애니메이션 "+N" 등)은 넣을지 말지 결정하고 이유를 적는다. 범위를 과하게 키우지 않는다.
4. 조작 — 방향키(및 WASD 여부), 터치 스와이프 임계값, 입력 중 애니메이션 처리.
5. 화면 구성·디자인 — 레이아웃 스케치(텍스트), 색 체계(라이트/다크 토큰 목록과 타일 값별 색 규칙), 애니메이션(새 타일, 합쳐짐, 이동), `prefers-reduced-motion` 대응.
6. 파일 구조 — `apps/tile-merge/` 안의 파일 목록과 각 파일의 역할. 예: `index.html`, `style.css`, `game.js`(순수 로직), `main.js`(DOM·입력), 필요하면 `preview.png` 또는 `preview.svg`.
7. 모듈 인터페이스 — `game.js`가 내보낼 함수 시그니처(예: 상태 생성, 이동, 게임 오버 판정). 테스트 가능하도록 난수 함수를 주입받는 구조.
8. Embed 계획 — 블로그 `index.html`에 들어갈 카드의 제목·설명, 미리보기 방식(이미지 vs iframe 중 하나를 추천하고 이유), 카드가 들어갈 위치 제안.
9. 수용 기준 — Review 단계에서 체크할 항목 목록(기능, 경계 사례, 모바일, 다크 모드, 콘솔 에러 없음, 규칙 위반 없음).
10. 범위 밖 — 이번에 하지 않을 것.

## 끝나면
