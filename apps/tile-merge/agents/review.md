# Review 서브에이전트 지침 — 모아 (tile-merge)

## 할 일
Build 단계에서 만든 `apps/tile-merge/` 웹앱을 **직접 실행해서** 검증하고, 결과를 `apps/tile-merge/review.md`에 쓴다. 문제가 있으면 고치고, 고친 뒤 다시 확인한다. 기준은 `apps/tile-merge/spec.md`(특히 9장 수용 기준과 "확정된 결정").

구현을 그대로 믿지 말고, 체크리스트 항목마다 실제로 해 보고 근거(측정값, 콘솔 결과, 스크린샷 관찰)를 남긴다.

## 수정 범위
- 고칠 수 있는 파일: `apps/tile-merge/` 안의 `index.html`, `style.css`, `game.js`, `storage.js`, `main.js`, `test.html`, `game.test.js`, `preview.svg`.
- 새로 쓰는 파일: `apps/tile-merge/review.md`.
- 수정 금지: `spec.md`, `agents/`, 그리고 `apps/tile-merge/` 밖의 모든 파일. git 명령 실행 금지(읽기 전용 `git status`/`git diff`도 쓰지 않는다).
- 임시 스크립트는 저장소 밖(시스템 임시 폴더)에 둔다.
- 검증 중 브라우저에 남긴 `localStorage` 값(`tile-merge:best-score`, `theme`)과 강제로 바꾼 화면 크기·색 모드는 끝나기 전에 원래대로 되돌린다.

## 실행 방법
- 로컬 서버: 브라우저 도구의 `preview_start`에 `name: "blog"`를 쓴다(`.claude/launch.json`에 `node serve.js 8000`으로 정의돼 있음). 셸로 서버를 직접 띄우지 않는다.
- 앱: `http://localhost:8000/apps/tile-merge/`, 테스트: `http://localhost:8000/apps/tile-merge/test.html`.
- 로직 테스트는 Node로도 돌린다(`game.test.js`는 DOM 없이 실행 가능한 ES 모듈).

## 꼭 확인할 것
1. spec 9장의 체크리스트 전부(기능·입력·모바일·다크 모드·접근성·코드 규칙).
2. 375px(모바일)과 데스크톱 폭, 라이트·다크 두 테마에서 화면을 본다. 블로그 `theme` 키를 `dark`/`light`로 저장했을 때 따라가는지, 다른 탭에서 바꾸면(`storage` 이벤트) 바로 반영되는지.
3. 스와이프: Pointer 이벤트를 합성해서 네 방향과 30px 미만 무시를 확인한다. 보드 밖에서는 페이지가 스크롤되는지.
4. `prefers-reduced-motion: reduce`에서 애니메이션 없이 동작하는지(에뮬레이션이 안 되면 CSS·JS 코드로 확인하고 그렇게 적는다).
5. `localStorage`가 예외를 던지는 상황에서도 게임이 동작하는지(예: `Storage.prototype.getItem/setItem`을 일시적으로 예외를 던지게 바꾼 뒤 새로고침 없이 동작 확인 + 인라인 테마 스크립트는 코드로 확인).
6. 하위 경로 배포 대비: `/`로 시작하는 경로·외부 URL이 없는지, `← 블로그로` 링크가 `../../`인지.
7. 코드 읽기 리뷰: 버그, 경계 사례, 메모리 누수(사라진 타일 DOM 제거), 이벤트 리스너 중복, 전역 변수, CLAUDE.md 코드 스타일.

## 알려진 문제 (고칠 것)
- **새 게임 확인 패널의 기본 포커스**: 지금은 첫 버튼 "새 게임"에 포커스가 가서 `Enter`를 두 번 누르면 바로 판이 지워진다. 실수 방지가 목적이므로 **"계속하기"에 처음 포커스**가 가도록 고친다(버튼 순서는 바꿔도 되고 그대로 둬도 된다). 승리·게임 오버 패널은 지금처럼 첫 버튼.

## review.md 형식 (한국어)
1. 요약 — 결론(통과/조건부 통과/실패), 고친 문제 수.
2. 검증 환경 — 확인한 화면 폭, 테마, 방법.
3. 체크리스트 결과 — spec 9장 항목별 ✅/❌/⚠️ 와 근거 한 줄.
4. 발견한 문제와 수정 — 문제, 원인, 고친 내용(파일:줄), 다시 확인한 결과.
5. 명도 대비 표 — 두 테마의 주요 쌍과 계산 값.
6. 남은 위험·확인 못 한 것 — 실제 기기 터치, 오래된 브라우저 등.
