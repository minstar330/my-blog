## 2. 게임 규칙

### 2.1 격자
- 4×4 고정. (`size` 인자는 로직에서 받아 두되 UI는 4만 쓴다.)

### 2.2 새 타일 생성
- 게임 시작 시 빈 칸 중 무작위 2곳에 타일을 1개씩 만든다.
- 이동이 일어난 뒤(실제로 타일이 하나라도 움직였거나 합쳐졌을 때만) 빈 칸 중 무작위 1곳에 1개를 만든다.
- 값: **2가 90%, 4가 10%**.
- 난수 사용 순서(테스트 재현용으로 고정): ① `random()`으로 빈 칸 인덱스 `Math.floor(random() * empties.length)` 선택 → ② `random() < 0.9 ? 2 : 4`로 값 결정. 빈 칸 목록은 행 우선(위→아래, 왼→오른) 순서.

### 2.3 이동·합치기
- 방향: `up`, `down`, `left`, `right`.
- 각 줄(행 또는 열)을 이동 방향 쪽으로 빈 칸 없이 민다.
- **이동 방향 앞쪽부터** 이웃한 같은 값 두 개를 하나로 합친다. 합친 타일 값은 두 배.
- **한 번의 이동에서 한 타일은 최대 한 번만 합쳐진다.** 합쳐서 생긴 타일은 같은 이동 안에서 다시 합쳐지지 않는다.
- 경계 사례(왼쪽 이동 기준, `·`은 빈 칸):

| 이동 전 | 이동 후 | 얻는 점수 | 설명 |
|---|---|---|---|
| `2 2 2 2` | `4 4 · ·` | 8 | 두 쌍이 각각 합쳐짐 |
| `2 2 4 ·` | `4 4 · ·` | 4 | 새로 생긴 4는 기존 4와 다시 합쳐지지 않음 |
| `4 2 2 ·` | `4 4 · ·` | 4 | 앞쪽 4는 짝이 없음 |
| `2 2 2 ·` | `4 2 · ·` | 4 | 앞쪽 두 개가 먼저 합쳐짐 |
| `2 · · 2` | `4 · · ·` | 4 | 빈 칸을 건너뛰어 합쳐짐 |
| `8 4 4 8` | `8 8 8 ·` | 8 | 가운데 쌍만 합쳐짐 |
| `2 4 8 16` | 그대로 | 0 | 움직임 없음 |
| `4 4 8 8` | `8 16 · ·` | 24 | 두 쌍 모두 합쳐짐 |

- **움직임이 없으면**(모든 타일 위치·값이 그대로) 상태를 바꾸지 않고, 새 타일도 만들지 않으며, 점수도 변하지 않는다.

### 2.4 승리
- 이동 결과로 **2048 타일이 처음 생기면** 승리 화면을 띄운다(`won = true`).
- 승리 화면 버튼: **"계속하기"**(같은 판을 이어서, `keepPlaying = true`), **"새 게임"**.
- 계속하기를 고른 뒤에는 4096 이상이 생겨도 승리 화면을 다시 띄우지 않는다.
- 승리 화면이 떠 있는 동안 이동 입력은 무시한다.

### 2.5 게임 오버
- 새 타일을 만든 뒤 판정한다: **빈 칸이 없고, 상하좌우로 이웃한 같은 값이 하나도 없으면** 게임 오버(`over = true`).
- 게임 오버 화면: "더 움직일 수 없어요" + 최종 점수 + **"다시 하기"** 버튼.
- 같은 이동에서 2048 달성과 게임 오버가 동시에 일어나면 게임 오버 화면만 띄우고, 문구에 "2048 달성!"을 덧붙인다.
- 게임 오버 상태에서 이동 입력은 무시한다.

## 3. 점수판

### 3.1 넣는 것
- **현재 점수**: 합쳐서 생긴 타일 값의 합을 누적한다. (`2+2→4`이면 +4)
- **최고 점수**: 현재 점수가 최고 점수를 넘는 순간 바로 갱신하고 `localStorage`에 저장한다.
  - 키: `tile-merge:best-score`
  - 읽을 때 0 이상의 정수가 아니면 0으로 본다. 읽기·쓰기 모두 `try/catch`로 감싸고, 실패해도 이번 방문 동안은 메모리 값으로 보여준다.
- **새 게임 버튼**: 점수가 0이면 바로 새 판을 시작한다. 점수가 0보다 크면 보드 위 패널(승리·게임 오버와 같은 패널 구조)로 "진행 중인 판을 끝낼까요?"를 묻고, **"새 게임"** / **"계속하기"** 버튼을 둔다. `confirm()`은 쓰지 않는다. 패널이 열린 동안 이동 입력은 무시하고, `Esc`는 "계속하기"와 같다. 승리·게임 오버 패널 안의 버튼은 확인 없이 바로 새 판을 시작한다.
- **"+N" 표시**: 점수가 오를 때 점수 숫자 옆에 `+N`이 잠깐 떠올랐다 사라진다(CSS 애니메이션, `aria-hidden="true"`).
  - 넣는 이유: CSS만으로 구현할 수 있어 비용이 작고, 어떤 이동이 점수를 냈는지 바로 알 수 있다.
- **표시 위치**: 제목 아래, 보드 바로 위의 한 줄 점수판(5.1 스케치).

### 3.2 넣지 않는 것
- **되돌리기(undo)**: 넣지 않는다. 상태 이력 관리와 "되돌린 점수" 처리 규칙이 추가되고, 퍼즐의 긴장감이 줄어든다. 이번 범위를 넘는다.
- **진행 중인 판 저장**(새로고침 후 이어하기): 넣지 않는다(열린 질문 참고). 저장된 상태의 유효성 검사까지 필요해져 범위가 커진다.
- 순위표, 이동 횟수, 시간 기록: 넣지 않는다.

## 4. 조작

### 4.1 키보드
- 방향키(`ArrowUp/Down/Left/Right`)와 **WASD**(`w/a/s/d`, 대소문자 무관)를 지원한다.
- `keydown`을 `document`에서 받는다. `Ctrl`, `Alt`, `Meta` 키가 눌려 있으면 무시한다(브라우저 단축키 보호).
- 게임 입력으로 처리한 방향키는 `preventDefault()`로 페이지 스크롤을 막는다. 처리하지 않은 키는 건드리지 않는다.
- 승리·게임 오버 화면이 떠 있을 때는 방향키를 게임에 보내지 않는다(버튼 사이 이동은 `Tab`).

### 4.2 터치 스와이프
- **Pointer Events**(`pointerdown` / `pointerup` / `pointercancel`)를 보드 요소에서 받는다. 마우스 드래그도 같은 방식으로 동작한다.
- 보드에 `touch-action: none`을 주어 보드 위 스와이프가 페이지 스크롤·확대를 일으키지 않게 한다. 보드 밖에서는 평소처럼 스크롤된다.
- 판정: 시작점과 끝점의 차이 `dx`, `dy` 중 절댓값이 큰 축을 방향으로 삼고, 그 크기가 **30px 이상**이면 이동. 30px 미만이면 무시(탭으로 간주).
- 한 번의 스와이프는 한 번의 이동만 만든다(이동 중 연속 판정 안 함).
- 멀티터치는 첫 포인터만 추적한다.

### 4.3 입력과 애니메이션
- 이동 애니메이션(약 120ms) 중에 들어온 입력은 **1개까지 대기열에 넣고**, 애니메이션이 끝나면 처리한다. 그 이상 들어온 입력은 버린다.
- 게임 상태는 입력 즉시 순수 함수로 계산하고, 화면은 그 결과를 따라간다(로직이 애니메이션을 기다리지 않음).
- `prefers-reduced-motion: reduce`이면 애니메이션 시간이 0이므로 대기열 없이 바로 처리한다.

- 전체 컨테이너 `max-width: 28rem`(약 448px), 가운데 정렬.
- 보드 폭: `min(100vw - 32px, 28rem)`, `aspect-ratio: 1`. 칸 간격 8px(넓은 화면 10px).
- 승리·게임 오버 화면은 **보드 위에 겹치는 반투명 패널**(보드 크기와 같음)로 띄운다. 제목, 한 줄 설명, 버튼. `role="dialog"` + `aria-modal="false"` + `aria-labelledby`. 열릴 때 첫 버튼으로 포커스, 닫히면 새 게임 버튼(또는 보드)으로 포커스.
- 시맨틱 태그: `<header>`(뒤로 가기·제목), `<main>`(점수판·보드·버튼), `<footer>`(도움말).
- 375px에서 가로 스크롤 없음. 모든 버튼·링크 44×44px 이상.

### 5.2 테마 결정
- 앱 자체 CSS 변수로 라이트/다크를 정의한다. 블로그와 같은 선택자 패턴을 쓴다:
  `:root`(라이트) → `@media (prefers-color-scheme: dark) { :root:not([data-theme='light']) {...} }` → `:root[data-theme='dark'] {...}`.
- **블로그 테마를 따른다(읽기 전용)**: 앱은 블로그와 같은 출처(`minstar330.github.io`)에서 열리므로, `<head>` 인라인 스크립트가 블로그의 `localStorage` 키 `theme`(`dark`|`light`)를 읽어 `<html data-theme>`에 적용한다. 값이 없거나 읽기 실패면 OS 설정을 따른다.
  - `storage` 이벤트를 들어서, 블로그 탭(또는 부모 페이지)에서 테마를 바꾸면 앱도 바로 바뀐다.
  - 앱은 `theme` 키에 **쓰지 않는다**. 앱 안에는 테마 토글을 두지 않는다(블로그와 따로 노는 상태를 만들지 않기 위해).
  - `window.parent`/`window.top`에 접근하지 않는다. iframe으로 들어가도, 단독으로 열려도 같은 방식으로 동작하며 서버 기능에 기대지 않는다.

### 5.4 타이포그래피
- 폰트: 블로그와 같은 시스템 폰트 스택. 숫자는 `font-variant-numeric: tabular-nums`.
- 타일 숫자 굵기 700. 크기는 자릿수 기준 클래스로: 1~2자리 `calc(var(--cell) * 0.42)`, 3자리 `0.34`, 4자리 `0.27`, 5자리 이상 `0.22`. (`--cell`은 칸 크기를 CSS에서 계산한 변수)
- 점수판 숫자는 천 단위 쉼표(`toLocaleString('ko-KR')`).

### 5.5 애니메이션
- 타일은 격자 칸과 별도의 **타일 층**에 절대 위치로 놓고, `--row`, `--col` CSS 변수로 `transform: translate(...)` 위치를 정한다. 각 타일은 고유 `id`로 DOM 요소를 재사용해 위치만 바꾼다.
- **이동**: `transform` 120ms `ease-out`.
- **합쳐짐**: 두 원래 타일이 목표 칸으로 이동한 뒤 제거되고, 합친 타일이 `scale(1) → scale(1.12) → scale(1)` 160ms로 한 번 튄다.
- **새 타일**: 이동이 끝난 뒤(지연 120ms) `scale(0.4) / opacity 0 → scale(1) / opacity 1` 150ms.
- **"+N"**: 위로 16px 떠오르며 사라짐, 600ms.
- **`prefers-reduced-motion: reduce`**: 모든 `transition`/`animation`을 끄고 즉시 위치·값을 바꾼다. "+N"은 애니메이션 없이 600ms 동안 보였다가 사라진다. JS의 애니메이션 대기 시간도 0으로 한다(`matchMedia`로 판단).

### 5.6 접근성
- 상태 알림용 `aria-live="polite"` 영역(시각적으로 숨김) 하나: 점수가 오른 이동 뒤에만 "점수 1,284점, 16점 획득"처럼 알린다. 점수 변화가 없는 이동은 알리지 않는다(너무 시끄러워지지 않게).
- 승리·게임 오버는 패널 제목이 포커스를 받으면서 읽히고, 추가로 같은 내용을 live 영역에 넣는다.
- 보드 요소: `role="group"`, `aria-label="게임 보드, 방향키나 스와이프로 조작"`. 개별 타일은 `aria-hidden="true"`(타일 하나하나를 읽는 기능은 범위 밖).
- `:focus-visible` 스타일은 지우지 않고 `--accent` 2px 외곽선을 쓴다.
- 텍스트 대비 WCAG AA(4.5:1) 이상, 두 테마 모두.

## 7. 모듈 인터페이스 (`game.js`)

모든 함수는 **입력 상태를 바꾸지 않고 새 상태를 돌려준다**. 난수는 인자로 주입한다(`() => number`, 0 이상 1 미만).

### 7.1 자료 형태

```js
// Tile
{
  id: number,                 // 게임 안에서 고유. 상태의 nextId로 발급
  value: number,              // 2, 4, 8, ...
  row: number,                // 0부터
  col: number,                // 0부터
  previous: { row, col } | null, // 이번 이동 전 위치 (새 타일·합친 타일은 null)
  mergedFrom: [Tile, Tile] | null, // 합쳐져 생긴 타일이면 원래 두 타일(이동 후 위치 포함)
  isNew: boolean              // 이번 턴에 생성된 타일
}

// GameState
{
  size: number,               // 4
  grid: (Tile | null)[][],    // grid[row][col]
  score: number,
  won: boolean,               // 2048 이상을 한 번이라도 만들었는가
  keepPlaying: boolean,       // 승리 후 계속하기를 골랐는가
  over: boolean,              // 더 움직일 수 없는가
  nextId: number
}
```

### 7.2 내보낼 함수

```js
export const WIN_VALUE = 2048;
export const DIRECTIONS = ['up', 'down', 'left', 'right'];

// 새 게임: 빈 판에 타일 2개 생성

// moved가 false면 state는 입력과 같은 참조를 돌려준다
export function move(state, direction, random) {
  /* → { state: GameState, moved: boolean, scoreGained: number, justWon: boolean } */
}

// 한 줄을 앞쪽(인덱스 0)으로 밀고 합치기. 테스트용으로도 공개
// 예: slideLine([2, 2, 2, 2]) → { line: [4, 4, 0, 0], scoreGained: 8 }
export function slideLine(values) { /* → { line: number[], scoreGained: number } */ }

// 빈 칸 하나에 2(90%) 또는 4(10%) 생성. 빈 칸이 없으면 그대로 반환
export function spawnTile(state, random) { /* → GameState */ }

// 움직일 수 있는 방향이 하나라도 있는가
export function canMove(state) { /* → boolean */ }

// 승리 후 계속하기
export function continueGame(state) { /* → GameState (keepPlaying: true) */ }

// 테스트 편의: 숫자 2차원 배열(0은 빈 칸)로 상태 만들기 / 상태를 숫자 배열로 바꾸기
export function fromValues(values, { score = 0 } = {}) { /* → GameState */ }

```

- `justWon`: 이번 이동으로 처음 `WIN_VALUE`에 도달했고 `keepPlaying`이 아니면 `true`. `main.js`는 이 값으로 승리 패널을 띄운다.
- `move`는 내부적으로 방향에 맞게 각 줄을 뽑아 `slideLine`과 같은 규칙으로 처리하되, 타일 `id`·`previous`·`mergedFrom`을 채운다.
- 이동 시작 시 모든 타일의 `previous`, `mergedFrom`, `isNew`를 초기화한 뒤 계산한다.
- `over`, `won` 상태에서 `move`를 부르면 `moved: false`로 그대로 반환한다(단, `won && keepPlaying`이면 정상 진행).

### 7.3 `storage.js`

```js
export function loadBestScore() { /* → number (실패·이상값이면 0) */ }
export function saveBestScore(score) { /* → void (실패해도 조용히 넘어감) */ }
```

### 7.4 `main.js` 책임 (요약)
- `createGame({ random: Math.random })`로 시작, 입력 → `move` → 렌더링.
- 렌더링: 타일 `id`로 DOM 요소를 찾아 재사용, 없는 것은 만들고, 사라진 것은 이동 애니메이션 뒤 제거.
- 점수판·"+N"·live 영역·패널 갱신, 최고 점수 저장.
- 전역 변수를 만들지 않는다(모듈 스코프만).

## 8. Embed 계획

### 8.1 카드 내용
- 제목: **모아 — 숫자 타일 합치기**
- 설명: 타일을 밀어 같은 숫자를 모으면 두 배가 돼요. 키보드와 터치 모두 지원하고, 최고 점수가 저장돼요.
- 링크: `apps/tile-merge/` (같은 탭에서 열기. 앱의 "← 블로그로"로 돌아옴)

### 8.2 미리보기: **이미지(`preview.svg`) 추천**
- **iframe을 쓰지 않는 이유**
  - 보드의 `touch-action: none` 때문에, 모바일에서 목록을 스크롤하다 iframe 위를 지나면 페이지가 스크롤되지 않는다.
  - 방향키가 iframe 안에 포커스가 있을 때만 동작해 "왜 안 움직이지?" 혼란이 생기고, 포커스가 밖에 있으면 방향키가 블로그 페이지를 스크롤한다.
  - 목록을 열 때마다 게임 하나가 통째로 로드된다.
- **SVG 이미지를 쓰는 이유**: 몇 KB 수준으로 가볍고, 어떤 화면 폭에서도 선명하며, 직접 그릴 수 있어 외부 도구가 필요 없다.
  - 내용: 보드 일부(타일 5~6개, 2~128 색)와 "모아" 글자. 배경을 SVG 안에 직접 칠해서(어두운 남색 바탕) 블로그의 라이트/다크 어느 쪽에 놓여도 어색하지 않게 한다.
  - `<img src="apps/tile-merge/preview.svg" alt="모아 게임 화면 미리보기" width height>` (가로세로 비율 고정, 레이아웃 밀림 방지)

### 8.3 카드 위치 제안
- 블로그 목록 화면(`#/`)의 **"최근 글" 위에 "만든 것" 섹션**을 두고 카드를 넣는다. 글 상세 화면에는 보이지 않게 한다.
- 블로그 목록은 `js/main.js`의 `showList()`가 `#app` 안에 그리므로, `index.html`만 고쳐서는 목록 화면에만 카드를 넣을 수 없다. 그래서 Embed 단계에서는 `js/main.js`(섹션 렌더링)와 `css/style.css`(카드 스타일)도 고쳐야 한다 → **열린 질문 1**.
- 앞으로 앱이 늘어날 것을 생각해 `apps/index.json` 매니페스트(`{ "slug", "title", "description", "preview" }` 배열)로 카드를 그리는 방식을 추천한다. `posts/index.json`과 같은 방식.
- 카드 스타일은 블로그 토큰(`--surface`, `--border`, `--accent`)만 쓰고, 카드 전체가 링크(44px 이상 터치 영역), `:focus-visible` 표시 유지.
