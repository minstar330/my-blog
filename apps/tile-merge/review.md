# 모아 (tile-merge) 리뷰 결과

## 1. 요약

- **결론: 통과** (알려진 문제 1건, 새로 찾은 문제 1건을 고친 뒤 다시 확인함)
- 고친 문제: **2건** (둘 다 `main.js`)
  1. 새 게임 확인 패널이 열리면 "새 게임"에 포커스가 가서 `Enter` 두 번이면 판이 지워짐 → "계속하기"에 처음 포커스
  2. 2048을 만드는 이동의 애니메이션(120ms) 중에 새 게임 확인 패널을 열면, 이동이 끝날 때 승리 패널이 확인 패널을 덮어씀 → 확인 패널을 유지하고, 취소하면 승리 패널로 돌아가게 함
- 로직 테스트: Node 64/64 통과, `test.html` 64/64 통과.

## 2. 검증 환경

- 서버: 내장 브라우저 `preview_start { name: "blog" }` (`node serve.js 8000`), `http://localhost:8000/apps/tile-merge/`
- 화면 폭: 375×812(모바일 에뮬레이션), 1280×800(데스크톱)
- 테마: OS 다크(브라우저 기본) / OS 라이트(`colorScheme` 에뮬레이션), 블로그 `theme` 키 `light`·`dark`·없음
- 방법
  - 키보드: `document`에 `KeyboardEvent` 합성, 일부는 실제 키 입력(`Enter`, `Escape`)
  - 스와이프: 보드에 `PointerEvent`(touch/mouse) 합성
  - 정확성: `Math.random`을 시드 난수로 잠시 바꾸고, 같은 시드로 `game.js`를 페이지 안에서 따로 돌려 DOM 결과와 비교(검증 후 원래대로 되돌림)
  - 승리·게임 오버 패널: 원본 파일은 그대로 두고, 페이지 안에서 `main.js`를 가져와 시작 판만 `fromValues(...)`로 바꾼 임시 문서(blob 모듈)로 확인
  - `prefers-reduced-motion`: 내장 브라우저에 에뮬레이션 기능이 없어, 같은 임시 문서 방식으로 `matchMedia` 결과를 `true`로 바꾸고 reduced-motion 미디어 쿼리 안의 CSS를 강제로 적용해 확인
  - 명도 대비: Node로 WCAG 2.x 공식 계산
- 검증 뒤 되돌림: `localStorage`의 `tile-merge:best-score`·`theme`(처음에 둘 다 없었음 → 삭제), `sessionStorage` 비움, 화면 크기 에뮬레이션 해제, 색 모드는 원래 OS 설정과 같은 다크로 둠, 보조 탭 닫음.

## 4. 발견한 문제와 수정

### 문제 1 — 새 게임 확인 패널의 기본 포커스 (알려진 문제)
- **문제**: 확인 패널이 열리면 첫 버튼 "새 게임"에 포커스가 가서, 새 게임 버튼에서 `Enter`를 두 번 누르면 확인 없이 판이 지워짐.
- **원인**: `openPanel()`이 모든 패널에서 첫 버튼에 포커스.
- **수정**: `main.js:233` 확인 패널 내용에 `focus: 'cancel'` 추가, `main.js:255-258` 지정된 버튼이 있으면 그 버튼에, 없으면 첫 버튼에 포커스. 버튼 순서·모양은 그대로, 승리·게임 오버는 계속 첫 버튼.
- **재확인**: 실제 `Enter` → 패널 닫힘·점수 4 유지·포커스 새 게임 버튼, 다시 `Enter` → 패널 열림·포커스 "계속하기"(판 유지). 승리 위에서 연 확인 패널도 "계속하기" 포커스, `Esc`로 승리 패널 복귀.

### 문제 2 — 승리 이동 애니메이션 중 연 확인 패널이 덮어씌워짐 (새로 발견)
- **문제**: 2048을 만드는 이동 직후 120ms 안에 새 게임 버튼을 누르면 확인 패널이 열렸다가, 이동이 끝나는 순간 승리 패널로 바뀜. 사용자가 고르던 확인 창이 말없이 사라지고, `panelReturn`도 비어 있음.
- **원인**: `afterMove()`가 지금 열린 패널을 보지 않고 바로 `openPanel('win')`을 부름. (게임 오버는 상태가 즉시 `over`라서 새 게임 버튼이 확인 없이 새 판을 시작하므로 이 문제가 없음)
- **수정**: `main.js:264-271` `openResultPanel()` 추가 — 확인 패널이 열려 있으면 덮지 않고 `panelReturn`에 승리/게임 오버 패널을 넣어 둠(알림 문구는 그대로 live 영역에 넣음). `main.js:327,329`에서 사용.
- **재확인**: 같은 조작에서 이동이 끝난 뒤에도 확인 패널 유지, live 영역에 "2048 달성!" 알림, "계속하기" → 승리 패널(포커스 "계속하기") → 계속하기 → 패널 닫힘·포커스 새 게임 버튼.

### 고치지 않은 사소한 점 (참고)
- `loadBestScore()`는 `'1e3'`을 1000으로 읽는다. 0 이상의 정수 값이라 규칙 위반은 아니고, 앱이 쓰는 형식도 아니어서 그대로 둠.
- 최고 점수는 다른 탭과 동기화하지 않는다(`storage` 이벤트는 `theme`만 처리). spec 범위 밖.
- reduced-motion에서는 `animationend`가 오지 않아 `tile-new`/`tile-merged` 클래스가 요소에 남지만, 애니메이션이 꺼져 있어 화면 영향이 없고 요소가 지워질 때 함께 사라짐.

## 6. 남은 위험·확인 못 한 것

- **실제 기기 터치**: 스와이프는 합성 Pointer 이벤트로만 확인했다. 실제 손가락으로 보드 위에서 페이지가 스크롤되지 않는지, 보드 밖에서 스크롤되는지는 iOS Safari·Android Chrome 실기기에서 확인이 필요하다(`touch-action` 값은 확인함).
- **`prefers-reduced-motion` 실제 OS 설정**: 브라우저 에뮬레이션이 없어, `matchMedia` 결과를 바꾸고 해당 CSS를 강제로 적용한 방식으로만 확인했다.
- **인라인 테마 스크립트의 저장소 예외**: 문서 파싱 전에 `getItem`을 막을 수 없어 코드 읽기(`try/catch`)로만 확인했다.
- **2048 이후 4096 재표시 없음**: 브라우저에서 4096까지 직접 만들지는 못했고, 단위 테스트와 `justWon` 조건 코드로 확인했다.
- **오래된 브라우저**: 컨테이너 쿼리 단위(`cqi`), `aspect-ratio`, `rgb(r g b / a)` 문법을 쓴다. Safari 16 미만 등 구형 브라우저에서는 타일 크기가 깨질 수 있다.
- **화면 낭독기 실제 낭독**: live 영역 문구와 포커스 이동은 DOM으로 확인했지만 NVDA·VoiceOver로 실제로 들어 보지는 않았다.
- **GitHub Pages 하위 경로**: 상대 경로만 쓰는 것을 확인했고, 실제 `/my-blog/` 배포는 하지 않았다.
